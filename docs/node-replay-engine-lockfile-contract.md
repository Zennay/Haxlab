# Replay engine dependency lock and provenance

HaxLab's replay decoder and imitation extractor use `node-haxball` **2.3.1**, exactly pinned in `package.json`. A direct pin alone does not freeze the transitive dependency graph. `package-lock.json` now pins the full npm resolution tree.

## Reproducible installs

- The lockfile was generated by **npm 9.2.0** with `npm install --package-lock-only --ignore-scripts --no-audit --no-fund` using an isolated scratch copy of the exact repository `package.json` on the connected zSSH VPS (2026-10-19).
- Lockfile v3 captures 55 entries including the root package. Root and resolved `node_modules/node-haxball` both specify `2.3.1`.
- Registry-hosted resolved entries include npm-provided integrity values; these are not manually invented. A dependency upgrade must update `package.json`, the npm-generated lockfile and replay decoder provenance together.
- Use `npm ci` rather than floating install resolutions in an explicitly authorized fresh build workspace. This commit does **not** run a build, install runtime dependencies or upgrade the live replay sidecar.

## Delivery scope

The new file is dependency-resolution evidence only; no replay extractor/decoder semantics, training, promotion, models, player shards, live service or VPS project worktree are altered. The lockfile was generated in an isolated `/tmp` scratch directory to avoid modifying the dirty live zCloud checkout. No tests or QA suites were written or manually run under the 17 October product-delivery policy.

Source PR requires all existing exact-head CI, review and integration gates before merge. The old PR-less lockfile branch was not modified or treated as an active owner.
